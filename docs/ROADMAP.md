# HumanWire 开发路线图与协作进度

更新于 2026-11-24。当前版本为 v0.5.2，匹配和收信功能在提交 `94a2be1` 中完成。本页记录实现和验收进度。

HumanWire 让用户在自己的 Agent 里按兴趣匹配陌生人，并跟真人聊天。核心交付沿用 MCP 服务和聊天小窗。Octo 通过本地配置接入，对端可以使用其他宿主或独立小窗。

关键词由用户填写，或由各自的 Agent 按用户意图建议。公开介绍示例为「在做个人网站，想聊移动端排版」。发送字段以用户选择公开的内容为准。

## 验收记录

- 2026-11-24 本地运行 `npm test`，31 项全部通过。测试覆盖模拟对端、中继、本地 HTTP 接口、匹配状态、管理操作和工具元数据。
- 本地启动两个独立聊天端，浏览器检查桌面 1100 × 850 和手机宽度 390 × 844。通过双向聊天、`/` 前缀、公开介绍、共同话题、刷新回看、超时继续、取消、断线后再匹配和旧会话清空。未出现页面脚本错误和横向溢出。
- 通过原生与小窗两种 MCP 启动入口检查工具调用。小窗模式的模型可见工具不提供正文收发和图片读取接口，连接状态输出只包含管理信息。
- 真实两台机器跨网、系统桌面通知、浏览器本地翻译和 Octo 实际联动仍待验收。上面的浏览器检查使用本地模拟连接。

## 多人协作

- 待做事项先在对应行填写负责人、分支或 PR，以及会修改的文件。核心匹配和公开介绍共同涉及 `src/p2p.js`，开始前约定接口和提交顺序。
- 提交后标为「待验收」，附复现方式和测试结果。通过本地验收时写明证据范围，跨机器和宿主体验补上各自结果。遇到依赖时记录具体阻塞条件和下一步。
- 本地入口为 `npm test`。界面变化还需检查桌面和手机宽度。跨宿主验收至少记录版本、发起入口、匹配等待、断线重试，以及 AI 空闲时收到消息的显示位置。
- 功能结构见[架构说明](ARCHITECTURE.md)，收发与上下文边界见[客户端接入](INTEGRATION.md)。进度和未完成验收更新在本页。
